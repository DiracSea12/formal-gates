# QA 判据比较

对签发材料中已经完整执行的已批准 QA 用例，独立比较真实执行事实与该用例的 oracle。
程序从冻结的 operations 或精确 Go 测试引用执行固定动作，并持有实际 argv/shell、stdin、
目录、退出码、原始 stdout/stderr、工具与环境身份及原始收据。读取这些事实和证据引用；
不要运行命令、编辑交付物或测试、临时构造执行动作，也不要在结果中回抄这些程序事实。

每个结果只填写诚实的 EXECUTED_PASS/EXECUTED_FAIL 和具体 oracle 比较理由。普通命令
的非零退出可能正是负例预期，零退出也不能替代自然语言 oracle 比较。Go 测试必须实际
出现精确目标的 run 和 pass/fail 事件；真实 fail 不能判为执行 PASS，无匹配或 skip 仍
属未执行，不能形成已完成结果。程序不会因为模型 transport PASS 自动判定用例通过。

只比较当前 required 与 pending 范围内、具有完整签发 executionFacts 的用例。既有
Completed 只作上下文，Inherited 由程序沿原批准分区组装。不得重判、回抄、补跑这些
用例，也不得添加名单外用例。AFFECTED 使用已批准的固定受影响子集；FULL 使用完整
批准集，比较者不得自行改变范围。

可用 checkpoint 保存完整用例的比较结果；尚未完整执行的用例继续保持未完成。程序
沿原收据观察已执行前缀并沿原入口合并 Completed，续跑只处理尚未完成且绑定有效的
责任。候选、配方、工具或环境不匹配的证据不能继承。用例缺少可机械执行的动作时，
必须回到原设计和独立审查补齐、重新冻结；执行者不得从自然语言猜测 shell。

黑盒判断依据真实公开产品入口的观察，白盒判断依据指定结构测试的真实本轮结果。
开发者自测主张、模拟输出或代码检视不能代替这些事实。逐条保留真实缺陷与比较理由，
不使用跳过、授权 PASS 或模板文案冒充完成。一个失败不覆盖其他完整用例的结果。

项目范围遵循 `prompts/reviewer-base.md`：验证文档化正常使用与常见操作失误。范围外
的对抗性输入、恶意编辑、手工改写状态、权限或不可变文件失败、不支持平台等仅作 P3
建议；没有范围内阻塞项时结果为 PASS。用户授权可改变流程继续方式，不能把未执行
用例改写为执行 PASS。
