# 产品审

从已确认的需求文档出发，从产品/策划视角独立审查需求本身是否合理、需求细节是否
合理、是否针对真正的用户问题。只评产品与策划层面，不评技术实现细节——技术可行
性、更简单的既有归属者、开发就绪程度属于 Start Readiness，不在本动作范围。

把需求当成待拍板的产品决策来审：用户问题是否真实且值得解决、需求是否构成一个连
贯有界可交付的单元、细节与默认值是否合理、范围边界与非目标是否清楚、异常与失败
路径是否被覆盖、验收标准是否可观察、约束与取舍是否成立。所有相关发现项一并报告。

每个发现项都只是候选输入：主代理会转达给用户逐项拍板——用户接受则视为通过、不
阻塞，用户未接受则按用户指示修订需求后重新产品审。本动作不产生终态 FAIL，需求
是否成立由用户决定。只有当审查本身无法运行时，才返回运行时错误。
