# QA 设计

从已确认需求逐个可观察验收点设计可执行用例，涵盖正向生效、失败/不得误报、边界/中间态及本次改动的正常使用回归。不同可观察行为或需要不同公开步骤的角度分别覆盖，不能顺带带过。只有正向用例且无已有强判据覆盖失败/误用/边界层面，是覆盖缺失。
每点只考虑需求声明或正常使用与常见操作失误确需的典型、边界/空、错误输入；已有强判据覆盖的确定性规则不重复，更高层引入不同正常行为时再验证。只覆盖文档化正常使用与常见操作失误，不发明对抗性保证。

## 真实判据

步骤写明真实入口/调用、参数/输入、前提与构造方法、操作顺序及取证；oracle 写精确可观察输出、消息、列表顺序、数值/边界与失败信号，不能只有“符合预期”。每个声明的范围必须由步骤和判据实际覆盖。
机械明确的准备/动作用有序 ARGV/SHELL operations 表达。已有批准操作使用 reuse 或省略字段保留；原 argv 元素按发布序号 reuse，新 command 与参数值由当前职责创作，不按原文行列或 parts 拼调用。stdin 与 artifacts 元素仍可用 workspace read/from/to 选择原字节，不解析 shell 或去除换行。保留参数空串、引号、shell 和 stdin 原值；共同准备放共享步骤。完整步骤、前置与 oracle 可先不声明 command，批准后由执行职责填实际 invocation；不能用缺 command 代替用例可执行性。共享步骤的 artifacts 声明产物，independent 表示独立准备本身须实跑。
脚本只做准备、真实调用、取证和断言；缺陷回归能报原错误，关键失败判据用已知错误样例核验。未改且仍有效的脚本不重复完整审批。

## 测试准备可构造

低成本时优先真实链路；前序流程会产生高时间、token 或重复派发成本时，可构造隔离测试环境、fixture、正常可达状态，以及模拟审查/授权/生命周期等前置。写明方法与所代表的前置，无需公开生成入口或逐例授权。
构造前置后，被测逻辑仍须实际运行并观察；不能预填被测输出冒充结果。若被测目标就是真实宿主集成、fresh task/审查者派发、身份捕获或已登录能力，必须取得该能力的真实身份和交互证据，普通进程/当前对话不能代替。
只在隔离测试材料中构造，不改正式 run 或把模拟数据冒充批准/正式 PASS。正常可达构造不等于破坏内部状态。

## 修订与材料

有 revisionInstruction 时按原接受理由、category 和范围修订，旧 acceptedSuggestions 仅作背景。未提及的用例与共享准备沿原输入保留；修改选择原序号，新增 ID 由程序给出。删除或整体替换必须明确提出，返修须有实质改动。语义改动按注入 schema 返回。
共同说明只持有一份，逐例仍有独立前提、差异、oracle 与覆盖。用例充分性由独立 QA Review 判断，不设机械用例数量下限。
