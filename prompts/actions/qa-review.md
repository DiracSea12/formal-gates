# QA 审查

对照已确认需求、原覆盖上下文与待审原文，逐条独立判断尚未批准的 case/shared-step；不能抽样、按组背书或用其他 case 补足本 case。集合覆盖缺失可独立报告，不使有效用例自动失败。
构造正常前置不要求重跑前序流程。
有 revisionInstruction 时核修订是否满足原接受理由、category 和影响范围；旧建议不能代替本次要求。

## 每条用例六项

1. 入口与参数：既有入口核公开帮助/文档；开发前新增/修改入口核已确认契约，不能仅因基线尚无产物拒绝。缺实质契约是缺口。
2. setup、前提、fixture 构造与逐步顺序确实可达。
3. 当前指定环境具备工具和宿主能力。被测目标是新 task、真实派发、身份捕获或已登录能力时，须有实际能力及身份/交互证据，普通子进程不等价。
4. procedure、前置构造、取证方法和 oracle 完整且可真实照做。已声明 operations 或精确 Go 测试引用须核其原值；未声明 invocation 的用例可在批准后由执行 checkpoint 首次绑定实际命令，不能改变批准步骤或判据，不能自行执行 shell或凭零退出判 PASS。
5. oracle 对应已确认需求及流程时点/授权前置，无遗漏或额外承诺，不能把需耗尽后才有的授权写成提前成功。
6. 步骤与断言覆盖所声称的行为范围；只测字面样例、绕开边界或顺带提及不能证明更广覆盖。

任一项不成立该 case FAIL，并指出具体卡点和证据；步骤、前态、取证或判据缺口不能留给执行者补足；只缺 invocation 按已批准契约执行期绑定。本动作不设计替代用例。先查能跑、能判的实质阻塞，文字完整不能替代真实入口/工具/数据核验。空泛判据、含糊步骤等同未覆盖。

## 集合覆盖与测试材料

逐验收点核正向、失败/不得误报、边界/中间态及相关正常回归，不以逐需求点的捆绑检查代替。不同可观察行为/公开步骤的遗漏构成覆盖缺失；仅正向且无已有强判据覆盖失败/误用/边界也不足。典型/边界/错误已有强覆盖不重复；同确定性规则的高层重复只有新增正常行为才需要。
共同说明只独立核一次，变化时核全部引用者；每条 case 的特有条件、操作、证据、oracle 和覆盖仍独立判断。新改脚本核准备、调用、取证、断言，关键失败判据用已知错误样例；同版本有效脚本不重复完整审批。

集合 P1 发现须满足共享契约的独立范围/严重度/因果/复现证据，case FAIL 不自动证明 P1。可选 P2/P3 改进给具体对象、建议与理由；真实漏测、不可执行或错误 oracle 不可降为可选建议。字段、序号和继承内容由注入 Result contract/schema 定义。
