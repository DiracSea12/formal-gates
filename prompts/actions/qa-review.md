# QA 审查

对照完整已确认需求、design、reviewScope 和 retainedReview，独立审查尚未获有效批准的
source、point、case 与 shared step。review 的每条 decision 仅含 id/status，逐条给出 PASS/FAIL，
逐 ID 的判定依据写在 message；不添加 schema 未声明的字段。
不在本动作设计替代用例，不用其他 case 的有效性替代当前 case 的判断。

黑盒只读基线隔离工作区与当前需求，不检视生产实现、实现 diff、开发解释、白盒或其他
审查者结论。白盒读取完整候选与所有 case/test 引用，审查全部 test-owned 测试的质量、
真实断言与覆盖，不按作者区分职责。已有测试全绿、测试名或覆盖率不能替代独立判断。

## 每个待审条目的检查

先核对会阻塞执行和验收的问题，再检查其他范围内细节。每条未批准 case 完整读取原文，
独立核验以下五项并给出依据：

1. 入口与参数：黑盒使用文档化公开入口；已有工具与入口当前可用；开发前新增入口按
   已确认接口契约核对，不因基线尚无该功能判 FAIL。契约缺失必要细节仍是缺口。
2. 前置与顺序：setup、fixture、输入、操作依赖真实可达。可构造隔离环境中正常可达的
   前置，不要求真实重跑前序流程，也不要求前置有公开生成命令。
3. 环境能力：指定环境确实具备所需工具或宿主能力。若验收对象就是原生新任务、派发或
   身份捕获，须取得真实观测；普通子进程不能冒充原生任务。模拟材料只能充当前置。
4. 执行与取证：procedure 能照做，被测逻辑实际运行且留下对应证据；command.executable
   只能是一个程序名或路径，args 逐参数给出，不能把整条 shell 命令塞进 executable。
5. 判据与覆盖：oracle 是具体可观察结果，符合需求与流程时点，不遗漏承诺或添加未要求
   的结果；输入、实际断言和被验证行为对应。不能把含糊判据留待执行者补齐。

任一项实质不成立，该 case 为 FAIL，指出具体卡点；文字完整或字段齐全不能掩盖缺口。
逐用例 FAIL 直接导致本轮 FAIL，但不能据此自动把集合层 finding 定为 P1。

## 覆盖与继承

逐验收点核对正向、失败路径、边界/中间态与受影响的文档化正常回归面。不同可观察行为
须有明确独立验收点和直接覆盖，不以一笔带过的捆绑用例背书。真实漏测、不可执行或
错误 oracle 均阻止批准。已有强判据验证同一确定性规则且高层没有新增行为时，不要求
更高层重复覆盖。

共同准备只审一次，在 sharedStepDecisions 逐 shared ID 判定，并在 message 说明理由。各 case 的特殊前提、差异操作、
证据和 oracle 仍独立核验。共同说明改变时检查全部受影响引用者；新改脚本核对准备、
真实调用、取证和断言，关键失败判据用已知错误样例检查，不递归为全部测试写测试。

FULL 建立初次批准；AFFECTED 只重新审查变更或失效项，engine 继承其余有效批准。
未批准条目逐条处理，禁止抽样、模式扫描或合并背书；返回数量与待审集合一致。
对未变有效批准改判必须有具体依据，不为重复核对而重审。

## 发现项与结束条件

集合层问题可指出覆盖缺失而不否定本身有效的 case；在 message 中给出阻塞依据，不新增
findings 字段。达到 P1 的问题需独立说明需求、正常执行
路径、实际后果、延期影响和可定位证据，逐项核验范围、严重度、因果和复现。
无法满足实际后果与证据条件的表述不得用 P1 占位。

可选 P2/P3 用 suggestions 返回稳定 id、severity、problem、cases、changesAcceptance，
不自行处置，不将仅建议的整体结果改为 FAIL。engine 登记用户按 ID 采纳、延期或拒绝；
采纳改变共同路径、可执行性或验收含义时，重审受影响部分。

措辞、命名、格式、等价写法、假设性加固与范围外对抗性场景只作 P3，不新增审查修复轮。
同根因合并说明影响对象；完成未决集合与覆盖核验后结束，不继续雕琢同类变体。

冻结前在上述逐例判断中核对可达性与取证路径：按步骤追踪同一资源的前态与后态，
检查后一步前置是否被前一步破坏、依赖用例是否提供所需状态、候选和精确接口是否一致。
例如“先 Seal/abort，再在同一活动 run 上追加目标”若无受支持的新受理步骤，须指出
冲突步骤、受影响用例及应走的现有设计修订；不能让执行者重开 run 或放宽判据。
逐一定位实际命令、退出码、stdout/stderr 与语义判据的证据入口；缺少入口不能靠字段
齐全通过。必要精确参数同步到前置任务；只简化非验收前置，真实全链目标仍实跑。
检查公共操作的 scripts/qa-preparation.md 索引中入口、依赖、参数和适用版本；静态检查
只解析源文件（如 qa-static-check.py），不 import/source 会启动任务的脚本。
问题沿现有 QA 设计增量修订，不增加审查轮次或自行改冻结判据。
