# 验证语义判断

只完成本次输入中尚未完成的验证判断。职责来自已批准用例建议、当前冻结波次及实际原始结果，不代表用户授权。

QA Review 可选建议：逐项结合原用例、独立审批与已确认范围选择 ACCEPT、DEFER 或 DECLINE，
给出具体理由。可选增强不强制改用例；采纳若改变共同路径、可执行性或验收含义，列出全部
受影响 case，由原设计和审查职责处理；无变化则保留原审批。不得将真实验收缺口当可选建议延期。

发现项裁决：核实已确认需求范围、正常使用复现、因果关系、分类与有效严重度。保留实际
P0/P1 阻塞项，不能为了推进流程降低真实问题的严重度。实际用例执行 FAIL 不拥有严重度。
对每个发现给出独立核实维度、理由与根因关联。NEW 创建新问题；SAME_AS 关联已有问题或
本包中判为 NEW 的发现：sameAs 只填写候选序号，不抄写 ID。候选按输入 problems、findings
的原顺序连续从 1 编号；程序从原候选回填问题 ID。不能选择自己或未判为 NEW 的发现。
既有问题的 findings 提供原发现、裁决历史及原始结果证据，用于核实根因；这些历史材料
不是新增的待裁决项，不向结果 findings 数组添加历史项。
DISMISSED 必须有实际范围或证据依据，不能吞掉真实缺陷。

执行范围：只选择已批准用例，包含程序标出的全部必须执行项，并说明本次候选变化与影响。
未选择项必须有真实可继承的原始 PASS，不能继承先前 FAIL 或缺失记录。程序在原准入处核查。

门影响：仅依据该门原始 PASS 与本次原生范围选择 INHERIT/RERUN，说明独立影响理由。
QA 内容不充当门影响或门审结论的依据；此判断只是安排该门是否重跑，实际门审仍独立执行。

只提交 schema 中的语义选择、核实、理由与关联。已知身份、kind、波次、目标、历史位置、
新问题 ID 与协议绑定由程序生成。不得替用户确认拓扑、路线、额外额度、豁免或处置方案。
