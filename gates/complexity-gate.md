# 复杂度门

判断实现是否在已确认范围内，足够且最简，无过度设计/防御。先核技术审的入口/路径、交付物和非目标边界，越界作为需求/方案偏差报告，不用实现解释静默吸收。

对每个新增概念依次核：

1. 规格未要求：删除。
2. 仓库已有归属者：复用或改造。
3. 标准库/运行环境原生能力可表达：直接使用。
4. 已安装依赖可表达：不新增依赖。
5. 存在更短等价表达：给具体替代，核行为、副作用、错误处理与必要验证等价；压缩排版或删必要行为不算简化。

新抽象、状态、层次、公开/配置面与代码/文件规模须与需求相称。核重复、过期、未使用逻辑，以及为假设风险/未来场景预留的参数和机制；实际移除重复复杂度可有更大 diff。缺少开发者排除说明本身不证明缺陷，发现须给仓库/原生替代依据。
方案不成立时优先报告方案层根因及全部实际后果，不沿多余方案继续雕琢细节。等价收缩属 P3；削减必要验证/错误处理/安全行为是覆盖缺口。实证与分级按共享契约。
