# 实现质量门

五个维度分别核验并报告，同权重、互不替代；不重做方案可行性或复杂度判断。材料与分级按共享契约。

1. **需求覆盖**：逐条核已确认需求的实现路径，含确认场景及错误处理；不推断额外要求、不用重跑测试替代代码核验。
2. **实现与需求偏差**：核改动是否改变需求与既有设计的应有语义，是否绕过归属者/流程、错误合并或混入职责。
3. **架构与耦合**：独立核模块边界、归属、依赖方向、公开面、状态/缓存生命周期、失败语义与性能形态。核隐式跨模块协调、内部细节泄露、重复能力、生命周期冲突及平行有效路径，不能作为覆盖维度的附注。
4. **正确性与质量**：核正常边界、可读/可维护性、编码/校验、开发者测试、死代码、兼容残留和原生比较中的遗漏文件。性能/资源卫生须有改动直接导致的可观察证据：复杂度、热路径拷贝/分配、无界循环/逐行查询、N+1、泄漏、缓存失效，以及临时文件/日志/流程产物无节制或无归属退役。按实际维护/资源影响定级，能跑通不豁免可读性。测试在行为归属的最低层验证，更高层重复须有不同正常行为。
5. **过拟合与窄逻辑**：核整个已确认范围的规则是否贯彻，是否仅应付特定样例、隐藏分支或不当硬编码；需求明确限定的逻辑除外。

优先局部修复或删除，避免新机制；核清同根因影响面。开发者测试可审，独立 QA 测试材料按共享契约排除。
