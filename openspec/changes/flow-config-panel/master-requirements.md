
# 流程配置面板 · 主需求

> 状态：定稿。
> 需求归属：formal-gates 自身功能。
> 界面草稿：`openspec/changes/flow-config-panel/mockup.html`——已定稿的界面方案，开发时直接复用为面板前端基础（`go:embed` 嵌入），不另起新设计。注意它是演示页：假数据、演示开关、占位实现都要在开发期接真实后端并修改优化后才算交付；其流程图未体现真实的批次/分片结构（见 §3.1.1），接入时必须按真实结构改。

## 1. 目标

1. 提供一个图形化配置面板，用户可以在窗口里完成现在需要记命令或改 JSON 才能做到的事：选择启用哪些流程节点、为每个节点指定平台/模型/推理强度、设置各节点的自动轮数上限。
2. 配置可以保存为多套并命名，随时新建、重命名、复制、删除、切换。
3. 面板在受理阶段和 run 进行中都能随时呼出；运行中对未开始/未在跑节点的修改保存即生效，不需要额外确认。
4. 面板只是配置文件的编辑器：它写的和 `settings` CLI 写的是同一份配置文件，不引入任何特权写接口。启动确认与回退仍走既有确认路径（`confirm_start`、`confirm_control`）。
5. 面板能做的每一件事，跟代理直接说或用 CLI 必须能达到同样效果；窗口打不开的环境（SSH、容器、无桌面）功能不缩水。
6. Windows、macOS、Linux 三平台都可用。

## 2. 本次交付边界

### 2.1 范围内

1. **面板本体**：流程图画布 + 右侧检查器 + 配置库抽屉，浏览器 `--app` 模式独立窗口呈现。
2. **打开入口**：MCP 工具 `configure`（供代理调用，契约见 §3.7）、CLI `formal-gates config`。
3. **面板服务进程**：短命进程，承载面板页面；窗口关闭或空闲超时后退出；每个项目单实例。
4. **配置模型扩展**：五个轮数上限字段进入配置套件（`Configuration`）；`panelIdleTimeout`、`panelSelection` 进入全局设置；CLI 补齐到与面板对等。
5. **运行中生效语义改造**：run 按绑定的配置名现读库内当前值（详见 §5），替换现在 run 启动时冻结副本、运行中改配置须经 SELECT_ROUTE/SELECT_EXECUTION 确认的语义。**这是一次产品合同迁移**：门集合、QA 模式、节点开关的权威从 run 决定台账转到配置库；初始路线 Ask 保留（它同时是拓扑与开发计划确认的唯一通道），但其中“逐 run 选门子集”和配置快照字段移除；运行中改配置的 Ask 入口、受理时逐 run/分片选门、`confirm_start.disabledNodes` 与 `workflow start --nodes` 的逐 run 节点覆盖、`submit --configuration` 入口随之移除；不支持旧格式 run，旧路径删除不并存。
6. **受理路线改造**：取消用户手选 regular/lightweight 与受理路线概念；执行行为直接由所选配置的启用节点决定，无中间路线档位（详见 §3.2.1）。

### 2.2 范围外（明确不做）

1. 面板内不提供阶段回退操作；回退只能通过代理进行（既有 reset、需求变更两条路径，均经 `confirm_control` 确认），但面板与代理都必须明确告知用户存在这条路径。
2. 不提供“中止正在执行的调用并按新配置重跑本节点”的能力；正在执行的调用按派出时的配置跑完。
3. 不做 WebAuthn、配对码、会话秘密等放行机制——面板没有特权写接口；仅需廉价的同源防护（见 §5.1）。
4. 不提供全局快捷键、不提供矩阵/表格视图、不提供开机自启安装选项；默认不实现托盘常驻进程——仅当三平台托盘适配代价可接受时才重新评估。
5. 运行中不提供“把 run 换绑到另一套配置”的操作；要调整就编辑 run 绑定的那套配置。
6. 模型与推理强度列表不硬编码在程序里；各平台具体型号以运行时动态获取为准。
7. 对抗性加固（代理故意读进程命令行、手工改状态文件、操作鼠标键盘等）按项目既有边界只作 P3 建议，不要求新机制。

## 3. 功能需求

### 3.1 流程图与节点配置

1. **画布按真实结构画流程**，不是七个节点排成一条直线：
   - 产品审查 → 开发前技术审查 → 开发；
   - 开发按批次串行推进；拆分时各分片按依赖并行，每个分片包含自己的开发与分片门（分片内无 QA）；
   - 黑盒 QA 的用例设计/审查与开发并行进行；
   - 全部分片完成后主线合并，然后合并 QA 与合并门；
   - 之后验证循环：QA 执行与质量门并行 → 有问题业务返修 → 再验证。
     受理阶段批次/分片数量未知，画布用示意结构表达；运行中按 run 实际拓扑展示批次进度与分片列表。
2. **配置按职责节点设置，各批次/分片共享**：可配置职责共七个（产品审查、开发前技术审查、初始开发实现、黑盒 QA、白盒 QA、质量门、业务返修）。同一职责在所有批次/分片/合并处共用一份配置——点任一分片/批次节点改门集合或开关，效果等于改该职责本身，自动作用到所有分片/块；分片/块不可分割，不存在单独启用或配置某一个分片。
3. 点选节点，右侧检查器提供：启用开关、平台下拉、模型下拉（随所选平台动态获取）、推理强度档位。
4. 质量门节点可勾选普通门集合，须表达 `Gates=nil` 的语义（“全部门，含将来新增”）与显式枚举的区别；两种形态在 UI 中都要能选。质量门节点整体关闭时，普通门、分片门、合并门、返修成员门均不派发（与引擎现状 `FlowNodeEnabled("gate")` 一致）；合并门不在普通门勾选项中出现。合并 QA 的执行选择跟随白盒节点；白盒未启用时跟随黑盒；两者都关则不存在合并 QA。
5. QA 开关与底层字段的映射：
   - 黑盒启用 ↔ `QAModes` 含 `"blackbox"`；白盒启用 ↔ `QAModes` 含 `"whitebox"`；
   - 黑盒、白盒同时关闭 ⟺ `"qa"` 写入 `FlowSelection.Disabled`；重新启用任一时移除；
   - 文件中两者不一致时（`Disabled` 含 `"qa"` 但 `QAModes` 非空），以 `Disabled` 为准显示两者均关闭；用户再开启时同时规整两个字段。`QAModes` 为空且未禁用 QA 时按两者均关闭显示（与内建“默认”配置现状一致）。
6. 轮数上限字段（范围 1–64，默认 3；取值 1 表示第一个自动轮后即需授权）：
   - 产品审查、开发前技术审查：各自独立的自动审查轮数；跑满后每加一轮需用户授权。“一轮” = 一次审查轮。
   - 黑盒 QA、白盒 QA：各自独立的设计审查轮数（设计↔审查返工连续 FAIL 上限，达到后锁定等用户决定）。“一轮” = 一次设计返工。合并 QA 的设计审查轮数跟随白盒的值（画布不单列）。
   - 业务返修：最大自动返修轮数；只显示在业务返修节点。计数口径：底层实际计入“验证波次数 + 每批业务返修轮次（按门链深度计）”，不是单纯的 wave 数；标签沿用“最大自动返修轮数”，提示文案须注明真实口径。“一轮” = 验证波次与返修轮次各计一。
7. 关闭的节点显示为虚线框，原连线画出绕行虚线表示“跳过该节点继续走”。
8. 画布支持拖动平移、滚轮缩放、键盘方向键平移（焦点在输入控件时不平移）、双击复位；平移范围限制在内容不拖出视野的边界内；侧栏打开时边界扣除侧栏宽度。
9. 点空白处、点检查器关闭按钮或 Esc 收起右侧检查器；再点节点重新打开。点节点时若有节点会被侧栏遮挡，自动缩放平移使全部节点可见；缩到最小仍放不下时，保证被点节点可见即可。

### 3.2 两种运行上下文

1. **受理阶段**（代理带着待确认的受理候选调用 `configure` 打开面板）：
   - 所有节点可配置；配置库允许新建、重命名、复制、删除（受 §3.3 约束）。
   - **取消 regular/lightweight 路线档位**：配置须至少启用一个节点；全部节点关闭的受理校验失败。
   - 组合校验：启用 QA、质量门或业务返修而未启用开发时，提示该组合无法完成 run 并禁止“选好了”；全部节点关闭同样禁止“选好了”并提示至少启用一个节点。
   - 底部动作是“**保存**”与“**选好了**”：“保存”打开配置库抽屉进入保存模式（与 §3.4.2 同一交互，受理期可正常做库管理）；“选好了”在校验通过后关闭面板，`configure` 把本次选择返回给代理，代理用它调用 `confirm_start`，宿主原生确认框展示需求材料与本次配置，用户在框内确认一次即启动。面板本身不是启动确认；确认前须核验受理候选身份未失效。
   - 有未保存修改时点“选好了”，弹内嵌对话框：**保存并继续 / 取消**（保存到当前编辑配置，未命名的走“存为新配置”流程；run 只认配置名，不存在“不保存继续”）。
   - 受理模式与已有 run 互不排斥：存在未结束 run 时带 `intake` 调用仍进受理模式（并行 run 由此产生）；`superseded` 只表示该受理候选本身失效。
2. **运行中**（存在未结束 run）：
   - **按节点单独锁定**，判定真源为引擎提供的逐节点投影：
     - *已完成*：当前事实下引擎对该节点无再派发义务（含返修重派发；FreshOwed/纠正重发/需求重走等未来用户决定产生的新义务不计入）——只读。引擎须暴露该投影作为唯一真源，面板不自判。
     - *正在执行*：该节点存在已领取（有 SpawnReceipt）且未返回的派发——只读，提示“本次调用按原配置跑完，完成后下一次派发用新配置”。
     - *其余节点*（含已签发未领取派发所对应的节点、验证循环中暂未在跑的节点）：可编辑，改动从该节点下一次派发生效。
   - 守卫：保存后必须至少保留一个**仍可派发**的启用节点，否则拒绝并提示。“仍可派发”与“已完成”共用同一引擎投影口径：节点启用且当前事实下仍有未完成派发义务（含被待决用户决定阻塞的义务，如挂着轮数授权 Ask）。CLI/手工编辑造成“无任何可派发节点”时，引擎按 §5.5 停派并报告（停摆可恢复：改回配置即可继续）。
   - 运行中保存套用与受理期相同的组合校验（按未完成义务判）：若尚有 QA/门/返修的未完成义务而开发节点被关闭，拒绝并提示。
   - 已完成节点提示“已完成，如需回退请在对话里向代理提出”。
   - 底部动作按状态变文案：有未保存修改显示“保存并应用”，无修改显示“应用”（见 §3.4）。
3. **无受理候选也无 run**（用户自己打开或代理仅为管理配置打开）：面板只做配置库管理，没有“选好了”，空闲超时只关窗。存在 run 时按 §3.2.2 进入运行中模式。
4. **多 run 并存**：面板顶部提供 run 选择器，节点状态跟随所选 run；配置库徽章列出绑定该配置的所有未结束 run（含子 run 计入其 master，不单列）。编辑绑定多个 run 的配置时，保存栏显示**不阻断的提示**“此配置正被 N 个 run 使用”；覆盖非当前编辑的配置才弹确认。
5. **当前配置徽章与删改规则**：被未结束 run 绑定的配置标注徽章，**不提供删除与重命名**（可编辑、可复制）；`settings` CLI 的删除/重命名对绑定中配置同样拒绝。绑定判定按“名字在合并视图中能否解析到配置”：删除遮蔽层后被压住的同名低层配置浮出、run 继续按名现读，属预期行为；但删除当时名字仍被绑定的遮蔽层配置同样拒绝。绑定名单口径：引擎能正常打开的未结束 run（分片子 run 归属其 master）；打不开或损坏的 run 不计入。
6. **上下文转场**：
   - 所选 run 到达终态：显示“已结束”；若无其他未结束 run 且无受理候选，转为配置库管理模式。有未保存修改时保留编辑内容，不自动丢弃。
   - 受理面板打开期间该受理候选失效：`configure` 返回 `superseded`，面板转为运行中或配置库管理模式，“选好了”消失。失效的判定：受理候选文件缺失，或其材料 artifact 的 revision 与磁盘现状不一致；候选被别处用于启动 run **不构成**失效（并行 run 允许）。
   - run 状态、节点锁定态、徽章随轮询刷新（与 §3.5 的文件哈希轮询同节奏），保证代理推进 run 时面板不长期陈旧。

### 3.3 配置库

1. 配置名必填；面板拒绝创建与各层合并视图中已有名字重名的配置。手工编辑造成的跨层重名按层优先级（项目层覆盖用户层）生效，列表中标注来源层。重命名只动源层：项目层“A”改名为“B”后，用户层被压住的“A”会重新浮出成为该名的生效值，属预期行为，不做额外处理。
2. 内建虚拟配置“默认”不可删除、不可改名、不可被同名覆盖；`settings save --name 默认` 等同名操作在 CLI 同样拒绝。文件中遮蔽内建“默认”的同名条目加载时忽略，并在面板列表中标注。
3. “设为默认”复用现有启用指针 `configuration`（即 `settings use`），写项目层；文档中“默认配置”一律指启用指针目标，非内建“默认”。被设为默认的配置被删除时按现有行为回落到内建“默认”。指针悬空时 `settings use` 允许在加载失败的情况下只重写指针（校验目标存在于各层任一来源），作为修复通道。
4. 复制自动命名为“原名 副本”（重名递增编号）。
5. 存在未保存修改时，切换配置、新建配置、删除配置、点面板内关闭按钮前必须经过用户确认（保存 / 放弃 / 取消）。浏览器标题栏 X 键关闭只能给出通用原生提示（`beforeunload`），不要求三选一对话框；空闲超时自动关窗不弹确认（直接丢弃未保存修改，属于本条例外）。
6. 面板中所有用户输入的名字不做 HTML 拼接（防注入）。

### 3.4 保存语义

1. 保存即生效：写库成功后，绑定该配置的 run 在各节点下一次派发评估时读到新值（§5.2）。
2. **保存入口是配置库抽屉**：点“保存”或“保存并应用”打开配置库抽屉并进入保存模式，抽屉顶部出现醒目的保存栏，此时：
   - **点击列表中任一已有配置即把修改保存到它**：点当前编辑的配置一步写回不弹窗（多 run 绑定时的使用提示按 §3.2.4，不阻断）；点其他配置需一次覆盖确认；内建“默认”不可作为覆盖目标；
   - **“存为新配置”**：输入新名字（默认“当前名 副本”并保证唯一），可选保存层级（项目层 `.gates/config.json` 为默认，可选用户层 `~/.config/formal-gates/config.json`）。
     覆盖时保持被覆盖配置的原有层级；运行中保存到非绑定配置时须注明“不影响本次 run”。
3. 运行中无修改时点“应用”不弹窗：编辑的是绑定配置时提示“已是生效配置”；否则提示 run 实际绑定的配置名，并说明运行中不能换绑。

### 3.5 并发修改

1. 面板打开时记录所读每个 overlay 文件的内容哈希作为 revision；保存/删除时比对，不一致拒绝写入并提示重新加载。
2. 任一 overlay 文件在外部被修改时（定时比对哈希）：本地无未保存修改则静默刷新，顶部轻提示哪一层文件发生变化；本地有未保存修改则顶部弹出提示条，提供“重新加载（放弃我的修改）/ 用我的覆盖”。不做字段级 diff。
3. 删除前同样检查 revision 与“是否被 run 绑定”。

### 3.6 呼出、生命周期与空闲超时

1. 受理阶段进行到需要用户选择流程时，代理先用 `settings show`、`settings show --gates` 与 `settings execution-options` 的程序当前枚举，清楚列出可选节点及每项选择、配置选项与后果，不硬编码名单。主动说明面板选择和对话选择都可以、两者不互斥；按 `panelSelection` 默认呼出面板，默认开时仍调用 `configure`。面板已经打开后，用户也可以直接在对话选好；代理通过既有 `settings` 保存配置，并向 `confirm_start` 提供原 `intake` 与 `configuration`，经原选择校验接纳后关闭该受理的对应窗口、让原 `configure` 返回 `selected`，随后独立进行原生启动确认。用户不必先关开关或面板、不等超时、不再点面板；没有面板时对话选择不另开服务或窗口。两种呼出方式仍是口头叫代理调 `configure` 或自己终端跑 `formal-gates config`，之后随时能再呼出。面板保存和对话选择都不代表启动批准，也不自行触发正式流程；启动取消不创建 run。该指引写入面向代理的规则文档与 `configure` 工具描述。
2. 运行中随时呼出只有两种方式：告知代理由它调用 `configure`（等当前动作结束），或用户在自己终端运行 `formal-gates config`。呼出方式在路线选择时主动讲清一次；此后不专门重复，但代理本来就要对用户开口的时刻——需要拍板（授权、确认候选）、出状况（run 卡住、节点失败待处理）、阶段推进汇报、run 结束汇报——应顺带一并提醒；不为提醒面板单独发消息。用户主动问起时正常回答。
3. 面板服务是短命进程：页面定时发心跳，服务在所有页面心跳停止一段时间后退出；由代理拉起时通过 stdin-EOF/进程组（POSIX）或 Job Object（Windows）保证不脱离宿主；由用户终端运行的 `formal-gates config` 为前台服务，Ctrl+C 结束。不得留下孤儿进程。重复拉起被委托进既有实例时，新窗口的生命周期归属既有实例的服务进程。
4. **每个项目单实例**：服务启动时在 `.gates` 下写实例文件（如 `panel-instance.json`：pid、端口、窗口管理接口地址），并用现有协调锁（`internal/coordination` 的内核锁）占位；重复拉起时读实例文件请求既有实例打开新窗口，不重复开端口；实例文件失效（进程已死）则清理后正常启动。
5. 面板服务只绑定 127.0.0.1 随机端口；浏览器使用**按项目隔离的**用户数据目录（`formal-gates/panel-browser/<项目标识>`），服务通过关闭自己拉起的浏览器进程来关窗（`window.close` 在 `--app` 下不可靠，不得作为唯一手段）；退出时清理端口与实例文件。
6. **空闲超时**：全局设置整数字段 `panelIdleTimeout`（秒，默认 300，范围 0–86400，0 表示不超时；进 `settings` 整数字段编辑路径），受理与运行中共用。计时以页面内最后一次用户操作（键盘、点击、滚动、拖动）为准：
   - 受理阶段：超时 → 关闭面板，`configure` 返回 `timeout` 并以启用指针目标作为本次选择；代理照常调用 `confirm_start`，宿主确认框照样等用户点击，不存在无人确认的启动。未保存修改丢弃。
   - 运行中或配置库管理模式：超时 → 关闭窗口，未保存修改丢弃。
7. **面板选择模式开关**：全局设置布尔字段 `panelSelection`（默认开，`EditField` 需补布尔解析，CLI 可 `settings set panelSelection true/false`），面板内提供开关，CLI/对话可同等切换。开启默认弹面板，关闭默认不弹；开关不使两种方式互斥。面板已开时仍接受对话选择，用户不必关闭开关或先关闭面板；对话选择经既有校验接纳后关闭对应受理窗口。明确要求面板时代理可带 `force` 参数打开。用户自己终端运行 `formal-gates config` 不受该开关影响。开关只影响默认呼出，不代替 `confirm_start` 或控制操作的真人确认。

### 3.7 `configure` 工具契约

1. 入参：`root`（可选，缺省当前目录）、`intake`（可选，受理候选序号；带上即受理模式，与是否存在 run 无关）、`force`（可选，`panelSelection` 关闭时仍强制打开）。
2. 调用阻塞到面板关闭或选择完成为止，但 `configure` 等待不独占同连接其它控制调用，普通控制调用及原生确认仍互斥。面板点击与对话选择复用同一选择校验与会话结果；对话通过既有 `confirm_start.configuration` 选择，关闭对应窗口、解决原等待者后独立请求启动确认，不新增 MCP 选择参数。宿主取消/超时该调用时，面板窗口保留；对同一 `intake` 再次调用时复用已开的窗口（同一项目单实例服务内按 intake 区分窗口，不同 intake 可各自开窗）。
3. 返回：
   - 受理模式：`selected`（带配置名与关闭的节点）/ `timeout`（同上，为启用指针目标）/ `cancelled`（用户关窗未选）/ `superseded`（受理候选已被替代或失效）；`cancelled` 与 `superseded` 本身不触发启动；用户随后明确对话选择时重新校验当前候选，失效则重新预检与展示，再沿原生确认处理。页面心跳丢失导致服务退出按 `cancelled` 返回。
   - 其他模式：`closed`。
   - 面板无法打开（无桌面、无可用浏览器）：返回 `unavailable` 并带原因，代理改走对话方式并说明现状。
   - `panelSelection` 关闭且未带 `force` 时直接返回 `disabled`，不开窗口，代理改走对话选择。
4. 用户在自己终端运行 `formal-gates config` 时没有代理在场，不受理：存在 run 时按 §3.2.2 打开运行中模式，否则打开配置库管理模式。

### 3.8 功能对等

1. 面板的全部操作必须能通过 CLI/对话完成同等效果：查看与选择配置、改节点开关/平台/模型/强度/轮数、管理配置套件（新建/重命名/复制/删除/设为默认）、切换面板选择模式、受理选择。
2. 对等性天然成立：面板与 CLI 写同一份配置文件，引擎读同一来源。CLI 需补齐：五个轮数上限与 `panelIdleTimeout`/`panelSelection` 的读写、配置 `rename` 命令、§3.2.5 的绑定拒绝、§3.3.2 的内建“默认”同名拒绝、`configuration` 指针写入时校验目标存在。
3. `configuration` 指针悬空（手工破坏等）时：面板与引擎派发同样按 §5.5 “停下并报告”处理，不静默回落；修复通道为 §3.3.3 的 `settings use` 指针重写。
4. 远程/无桌面环境以 CLI + 对话为准：面板打不开时，代理说明现状与可选配置，用户在对话中指定，代理用 CLI 落实。

## 4. 界面与体验

1. 采用“流程画布 + 右侧检查器 + 左侧配置库抽屉”布局。配置库抽屉默认打开，可点遮罩或按钮收起，再点“配置库”按钮重新打开。
2. 运行中节点有呼吸/流动动画；关闭节点的连线重新布线；切换配置时变化的节点闪动提示；保存成功短暂对勾；冲突提示条滑入。
3. 已选节点高亮；已配置的平台/模型/强度以 chip 摘要显示在节点上。
4. 删除、覆盖、丢弃未保存修改等破坏性动作使用面板内确认对话框（红色确认），不使用浏览器原生 `prompt/confirm/alert`。
5. 接入时须对草稿做的改动：移除演示元素（受理/运行中切换、模拟冲突按钮、假数据）、冲突条的“查看差异”按钮、绑定中配置的重命名入口；受理底部按钮改“选好了”，运行中底部为单按钮动态文案；流程图按 §3.1.1 真实结构改；分片/批次节点编辑按 §3.1.2 共享语义（改任一等于改全部，UI 须标注）；门集合勾选须支持“全部门（含将来新增）”形态；正在执行节点只读提示文案按 §3.2.2。

## 5. 生效语义

1. **为什么不需要放行机制**：面板只写配置文件，这是代理本来就能做的事（`settings`、直接编辑 JSON）。启动与回退这类需要防代理伪造的命令不经过面板 HTTP 接口，仍由宿主原生确认。面板 HTTP 接口只做“读状态”与“写配置库”两类事，不开放远程调试端口。**同源防护**：任意网页可向 127.0.0.1 发请求，因此所有写请求必须校验 `Origin`/`Host` 头并携带服务启动时下发的随机 token（注入页面/URL），读接口只校验 `Host`。
2. **配置权威与解析**：配置库是门集合、QA 模式、节点开关、执行选择、轮数上限的唯一权威来源。run 启动时记录绑定的配置名与**初始应用快照**（分片 child 记名继承 master 的绑定名并同样现读）；引擎每次派发评估时按该名读库内当前值，与 run 状态比对，差异（含字段级新值）作为账本事实记录后生效，形成按时间序的**应用值历史**；派发记录保存实际使用的值供审计。
   - 已执行中的调用不受影响；尚未被领取的派发改用新值（复用现有 `rebindUnclaimedExecution` 能力）。
   - **关闭节点对已领取/正在执行的调用不立即生效**：变更记入应用值历史为“待生效”，该节点视为“关闭中”；其已签发未领取的派发按既有处置路径作废，已领取调用按原配置跑完后节点才算关闭、此后不再派发。配置对账永远不触发 `stopControlledWorkers` 类撤回——撤回已签发调用仍只属于记录在案的用户决定（reset 等）。面板把“关闭中”节点标注出来。
   - 待决 Ask 中由配置库取值的字段，批准时按当前库值重算；因配置变更使 Ask 选项失效的，Ask 作废重发（有自动作废先例可循）。
   - 对账在每次派发评估时进行；“保存即生效”中的“即”指下一次派发评估，不是写入瞬间。读库瞬态失败（编辑器非原子保存等）跳过本次对账沿用上次应用值，下一次评估重试；持续读不出或解析失败按 §5.5 停派报告。
   - **已进入主线的分片**：分片进入主线后，其剩余义务由主线职责承接（沿用 `SliceEnteredMainline`/claims 判定），之后的配置变更对该分片记为“已越过”写入应用值历史而不实际应用；主线正在对账该片输入（claims 未定）期间，改变验证路线的变更推迟到对账完成后评估，届时已进主线同样记为越过。分片未完成的活由主线的合并 QA/门/返修按 master 的配置承接；面板在 master 的分片列表中把已进主线分片标注“已进主线，随主线配置”。
3. **运行中改节点开关、QA 模式、门集合**：对未完成节点生效。由此引起的未完成工作处置（重做/续用、验证路线重绑、QA 工作区清理、审计记录）**复用现有 SELECT_ROUTE 批准后的同一处理路径**，只是不再生成 Ask 等待确认，不另写第二套实现。
   - **初始路线 Ask 保留**：它同时承载拓扑确认与开发计划确认；其中“逐 run 选门子集”与配置快照字段移除（改为按库值填充、批准时重算）。`RouteConfirmed`、`SelectedGates`、`FlowSelection` 等状态字段仍为台账事实，但来源改为应用值历史而非决定快照。
   - **删除清单**（不并存）：运行中改配置的 SELECT_ROUTE/SELECT_EXECUTION Ask 入口、受理路线 Ask 与分片 route Ask 中的选门子集能力、`confirm_start.disabledNodes` 与 `workflow start --nodes`/`--disable-node` 的逐 run 覆盖、`submit --configuration` 及 `--flow-node/--qa-mode/--gate/--all-gates/--no-gates/--execution-node/--platform/--model/--effort` 等逐 run 配置参数、`RouteConfigurationRequired`/`routeConfigurationState` 谓词、`"qa"` 伪节点执行选择腿（改由 §3.1.4 的黑白盒跟随规则替代）、分片 `InheritedExecution` 创建快照腿、run 状态中的冻结 `Configuration` 腿、`EffectiveConfiguration` 的决定合并腿、`facade.ConfigurationInput`/`prepareConfiguration` 的决定装载面。被移除控制类型的旧决定与 Ask 事件不保留解析兼容；当前合法事件的精确重放保持不变。
   - 应用值历史的每条记录须携带与决定台账同形的预览与生效内容，使下游读取方（约 20 处经 4 个汇总函数）改从该历史读取而调用点不动；**禁止伪造“已批准的决定”记录**（决定台账只记真实用户决定，伪造违反撤回授权原则）。
   - 依赖旧事实源的残量谓词（`flowNodeWasDisabled`/`phaseLedgerFloor` 读节点禁用历史、`topologyRouteConfirmed` 读路线决定存在等）迁移到应用值历史与保留的初始路线 Ask。
   - （开发前须先核实该处理路径能否不经 Ask 直接复用，见 §8.1。）
4. **轮数上限的生效与账本**：上限记录为**生效区间账**——（值，生效序号）序列；series/wave 创建时记入当时生效值，运行中修改时追加新记录。每次判定“是否还能自动再跑一轮”读当时最新记录；每一轮的合法性按**该轮执行时生效的上限**核对，因此下调上限后已完成的轮次不被判非法，已授权轮不收回。`integrity` 对账按此规则重写，不再以创建时固化值与常量比对为唯一基准；当前格式在创建时写齐区间账，派发时记录原轮身份，不在加载时补旧账。
5. **配置不可用统一停派报告**：绑定名解析不出、启用指针悬空（修复通道见 §3.3.3）、配置库整体读取失败（坏 JSON、未知字段等）、无任何可派发节点，均使 run 在下一次派发前停下，通过 `Next`/`Show` 投影报告具体原因，等待用户处理；不静默回落到其他配置。
6. **启动与回退确认不变**：`confirm_start`/`confirm_control` 的确认行为原样保留；`confirm_start` 的 `route` 与 `disabledNodes` 参数一并移除，确认框只展示材料、配置与启动操作。回退（reset、需求变更）候选也可用 `workflow submit` 由用户自行提交。
7. **run 格式与恢复边界**：不支持旧格式 run（冻结配置、缺失应用历史或轮数区间账、旧配置型 SELECT_ROUTE/SELECT_EXECUTION Ask 与决定），不做跨安装重装或升级的 run 接管；沿现有版本与安装身份检查明确拒绝，保留原文件，不自动迁移或清理。同一当前版本、同一安装身份内的正常中断恢复、重复事件精确重放、并行与分片继续支持；当前真实批准决定的工作来源和轮次授权不变。

## 6. 工程约束

1. 单一二进制交付：面板前端用 `go:embed` 打进 `formal-gates`；面板服务与 CLI 共用同一套后端。
2. 窗口优先走浏览器 `--app`；找不到支持的浏览器时用普通浏览器窗口打开同一地址。浏览器同 profile 单例转发行为三平台不一（如 macOS `open` 不转发 `--args`），二次拉起开窗方式须先验证后实现。
3. 预期零新增依赖：不引入 webview、GUI 框架、托盘库、WebAuthn 库。
4. 轮数上限可配置化须修改引擎：把 `automaticRoundLimit`（review.go）、`automaticValidationWaveLimit`（validation.go）两个常量与 QA 前置审查连续 FAIL 上限（`prewaveBlocked` 内联字面量）拆为五个每节点字段收进 `Configuration`，字段名定为 `roundLimits`（map，键：`product-review`/`tech-review`/`qa-blackbox`/`qa-whitebox`/`repair`，缺省按节点默认 3）；账本按 §5.4 改造（生效区间账、integrity 重写）。
5. 受理路线移除须同步 `workflow start --precheck`：删除 `--route` 参数与按路线分流语义，`structured` 解析改为总是进行（受理面板需要 REQ/AC 投影做校验）；材料格式校验移到“选好了”校验与 `confirm_start`。
6. 所有改动遵循项目代码准则：单一权威来源、正常执行与恢复共用同一业务路径、被替代的路径删除不并存。
7. 面板服务进程不残留孤儿进程；退出时清理端口、实例文件与临时资源。
8. 界面草稿里的 `prompt/confirm/alert` 一律不得进入实现。
9. 配套文档同步更新：`SKILL.md`（路线选择指引、disabledNodes 移除）、`references/formal-flow.md`（受理路线、门子集选择、运行中改配置、冻结语义）、`references/sliced-runs.md`（分片选门移除）、`references/user-configuration.md`（新字段、rename、绑定拒绝、生效语义）、`references/install-and-hooks.md`（`configure` 工具的宿主安装/发现说明）。
10. 面板与 CLI 的 revision 校验必须在 `editOverlay` 的内核锁内做读时哈希比对（否则检查与写入间有 TOCTOU 窗口）；settings 写路径增加“携带所读哈希”参数，面板与 CLI 共用。
11. 任务层面建议把“面板 UI”与“生效合同迁移”切成两个阶段实施，先迁移语义再接面板，降低单次改动面。

## 7. 验收示例

1. 受理：代理调用 `configure`（带 intake）→ 面板弹出 → 用户改配置点“选好了”（有未保存修改时先保存）→ `configure` 返回 `selected` → 代理调用 `confirm_start` → 宿主确认框显示需求与本次配置 → 用户确认 → run 启动并记录绑定配置名与初始应用快照。
2. 受理全部节点关闭点“选好了” → 校验失败并提示至少启用一个节点，面板不关闭；启用 QA/门/返修而未启用开发 → 面板提示组合不可完成且不关闭；启用任一节点但材料无 REQ/AC → 面板提示原因且不关闭。
3. 受理超时：不操作超过 `panelIdleTimeout` → 面板关闭，`configure` 返回 `timeout` 与启用指针目标；`confirm_start` 确认框照常弹出等待用户。
4. 受理期间候选文件被删或其材料 revision 变动 → `configure` 返回 `superseded`，面板切运行中/配置库管理模式；代理不得再调用 `confirm_start`。存在未结束 run 时带 intake 调用仍进受理模式（可产生并行 run）；候选被别处用于启动 run 不算失效。
5. 运行中：开发正在执行时把“质量门”的模型改掉并保存 → 开发当前派发不受影响；下一次门派发使用新模型（派发记录可查实际值）；已签发未领取的派发改用新值。
6. 运行中：已完成节点（引擎投影无再派发义务）与正在执行节点（已领取未返回）只读；验证循环中返修在跑时质量门节点可编辑；挂着授权 Ask 的 run 上改其他字段可正常保存（被阻塞的义务仍算可派发）；把配置改到无任何可派发节点 → 保存被拒并提示；经 CLI 造成同状态时引擎停派并报告。
7. 运行中把审查轮上限从 3 改为 5 → 尚未跑满的审查在第 4、5 轮仍自动进行，账本追记新上限；改为低于已用轮数 → 下一轮需授权，已完成的轮次按当时生效值核对、账本不被判非法。
8. 运行中保存后待决 Ask（其字段含配置取值）→ 批准时按当前库值重算；因配置变更选项失效的 Ask 作废重发。
9. 运行中超时不操作 → 窗口自动关闭，未保存修改不入库。
10. 代理通过 CLI `settings` 完成与面板相同的修改 → 引擎下一次派发读到相同值；`settings rename`/删除绑定中配置被拒；`settings save --name 默认` 被拒；`configuration` 指针写入不存在的名被拒。
11. 面板内绑定中配置无删除与重命名入口；遮蔽层删除场景经手工编辑配置文件制造（正规入口均会拒绝），低层同名浮出后 run 仍按该名现读（记录此边界行为）。
12. 编辑期间任一 overlay 文件被外部修改 → 顶部提示条标明哪层变化；保存时 revision 不一致被拒绝。
13. 多 run 并存：两个 run 绑定同一配置 → 保存后两者下一次派发都读到新值；徽章列出两个 run；分片记名跟随 master 现读。
14. run 到达终态而面板开着 → 显示“已结束”，无其他 run 时转为配置库管理模式，未保存修改保留。
15. 关闭面板选择模式 → `configure` 不带 `force` 返回 `disabled` 不开窗；带 `force` 或用户终端 `formal-gates config` 仍可打开；重新打开开关后恢复弹面板。
16. 同一项目重复执行 `formal-gates config` → 不开第二个服务端口，既有实例经实例文件收到请求打开新窗口；关闭全部窗口后服务进程退出，无残留进程与实例文件；宿主取消 `configure` 调用后窗口保留，重新调用复用。
17. 当前格式 run 创建即写齐初始应用历史与轮数区间账；同版本同安装身份下中断恢复与重复事件精确重放保持原事实。旧版本状态明确拒绝且不改写或删除原文件；不要求旧 run 升级接管。
18. 绑定名被手工删除 → run 在下一次派发前停下并报告该名字，不静默回落。
19. 无桌面环境：`configure` 返回 `unavailable` 并带原因 → 代理说明现状与选项 → 用户在对话中指定 → 代理用 CLI 落实，功能等价。
