# Design

改动集中在派发恢复路径与生命周期适配。

1. **续用优先的派发恢复**：主代理检测到被中断且**已认领**（CLAIMED，绑定了宿主身份、
   有可恢复的原代理）但未产出结果的派发时，先按宿主续用机制（Claude Code
   `SendMessage` 等）恢复原代理继续，而非立即 `staleOpenDispatches` 重开。未派发的
   OPEN 派发没有可恢复的子代理，不在续用候选内。续用可用性按宿主能力判断；不把续用
   能力作为硬依赖。
2. **回退路径**：续用不可用（宿主不支持 / 恢复失败 / 生命周期无法认证）时，保持现有
   `staleOpenDispatches` + 重开新派发 + 新零上下文代理路径（RQ-3-2）。
3. **生命周期适配**：续用完成的派发，start 事件在首次派发时捕获、stop 事件在续用完成时
   捕获，成对可认证（RQ-3-3）。RQ-3-4 的可审计性由既有不变量满足——claim-dispatch 把
   一个派发绑定到一个宿主身份、记录结果要求该 CLAIMED 派发，故同一派发的续用天然保持
   同一身份/同一结果映射；不新增续用标记字段或命令。
4. **SKILL 独立派发章节**：改为续用优先表述，但保留宿主能力条件（"若该宿主提供续用机
   制且生命周期可认证续用完成"）；对生命周期校验不可用的宿主（如 Codex/Cursor 提供
   商），RQ-3-2 的"生命周期无法认证续用完成"回退保持权威，不声称已文档化续用机制。

边界：续用机制是宿主能力，不强制所有宿主支持；不可用即回退，不加防御（RQ-3-5）。
