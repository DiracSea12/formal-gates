## Complete confirmed requirements

This delivery covers three related pieces of work:

1. The formal-gates intake wording must be unambiguous. A proposed solution is
   not requirement confirmation. After clarification, the agent must explicitly
   state that there are no remaining clarification questions when that is the
   case, then ask for confirmation of the complete requirement and solution in a
   separate confirmation. Route selection is a later, separate question. Before
   that confirmation, the agent must not select a route, write project files, or
   dispatch an agent. The current `SKILL.md` wording already contains this fix
   and is part of the delivery to verify.

2. Installing formal-gates for Claude Code, Codex, or Cursor must also install
   one managed intake rule into the host's applicable project guidance file.
   Reinstalling or upgrading must not duplicate the rule. An upgrade must
   replace any older managed rule text with the latest text. Uninstalling must
   remove every historical managed rule text while preserving unrelated user
   content, host hooks, and other configuration.

   The latest managed rule is:

   > 当用户请求创建、编辑、移动或删除任何项目内容时，必须先执行 formal-gates 受理流程：先澄清需求与重大技术选择；提出方案不等于确认；即使无待澄清问题也要明确说明无待澄清问题，并单独请求用户确认完整需求与方案；确认前不得选择路线、写入文件或派发代理。

   All historical versions of this complete text must be stored in
   `references/managed-rules.json`. The installer must inspect every stored
   version as an exact complete line or block, remove duplicates and old
   versions, and leave one latest rule. If no version is present, it appends the
   latest rule. The uninstaller uses the same complete version list to remove
   all managed text.

   The managed-file targets are:

   - Claude Code global: `~/.claude/CLAUDE.md`
   - Claude Code project: `<project>/CLAUDE.md`
   - Codex global: `~/.codex/AGENTS.md`
   - Codex project: `<project>/AGENTS.md`
   - Cursor project: `<project>/.cursor/rules/formal-gates.mdc`

   Cursor global continues to use the existing `~/.cursor/formal-gates`
   runtime and `hooks.json` integration; this change does not invent a global
   Cursor rules location.

3. The existing Codex hook fix must be included in the formal verification. The
   Codex installation must invoke `hook decide --provider codex`, return a
   Codex-compatible JSON block decision, and exit successfully so Codex consumes
   the decision. Claude Code and Cursor retain their existing deny exit-code
   behavior. This behavior is already implemented in the current worktree and
   must be proven by tests and the available Linux/Codex canary; it should not be
   reimplemented unless verification exposes a defect.

   Compatibility boundary: previous-version Hook formats, runtimes, and command
   formats are not supported. The installer guarantees installation,
   idempotent reinstall, and idempotent uninstall only for the Hook formats and
   runtime generated by this delivery. Any later Hook format change must update
   its ownership recognition and tests in the same delivery. This boundary does
   not waive the managed-rule catalog requirement above; all historical
   managed-rule text versions remain retained in the catalog and subject to
   exact migration and uninstall.

## Confirmed technical solution

- Add a JSON rule-version source under `references/managed-rules.json`. Validate
  that it contains an ordered, non-empty list of unique versions and complete
  rule texts; the last entry is the latest text used for installation.
- Extend the native installer with symmetric `uninstall` support using the same
  host and scope/project resolution as `install`. Uninstall removes the managed
  rule text, the formal-gates hook entries owned by the installer, and the
  formal-gates runtime directory for the selected target, while retaining
  unrelated content.
- Keep exact text/block matching. Do not use fuzzy matching or markers. The
  version source is the ownership record, and the user accepts the negligible
  risk of an unrelated document containing the exact same complete rule.
- Treat the managed rule as a newline-delimited block. Preserve the surrounding
  file's content and newline style as far as practical, and leave an empty
  Cursor rule file removable when it contains no unrelated content.
- Add focused unit tests for version loading, duplicate/old-version migration,
  append, uninstall preservation, all three hosts, both scopes, idempotent
  reinstall, and hook cleanup. Extend portable canary coverage for install and
  uninstall shape.
- Preserve the existing Codex hook implementation and its tests, and add the
  real same-host canary result to the delivery evidence when the installed
  Codex executable is available. A missing Codex executable is reported as
  unproven rather than converted into a PASS claim.
