# Design

修改 `prompts/actions/requirements-clarification.md`（catalog 文件，经 B2 目录 delta
容忍）与 CHANGELOG.md（仓库惯例）。

1. **澄清问答在受理阶段进行、不得跳过**：提示词用正面表述写明澄清问答在受理阶段（正
   式流程启动之前）进行——一次只问一个有实质影响的决策、检视仓库事实、不套固定问卷、
   呈现完整整合需求与技术方案、取得用户最终确认、把整合后的完整需求写入需求文件；除
   非确无会实质改变公开行为/验收/架构的决策需要澄清，否则必须先完成澄清问答、取得用
   户最终确认才能记录 PASS；不得跳过。全文不出现任何后续流程步骤名（如"第 2 步"），
   不把澄清问答或写文件与任何后续步骤联系起来。
2. **持久化**：把整合后的完整需求与决策写入需求文件（受理阶段、正式流程启动之前），
   作为本 run 的验收输入与事实来源。
3. **确认粒度**：明确"确认"= 呈现完整整合需求与技术方案并取得用户最终确认；PASS 只记
   录用户实际确认的内容。

保持精简：只改 `requirements-clarification.md` 与 CHANGELOG.md，不新增文件。
