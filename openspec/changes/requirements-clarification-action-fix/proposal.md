# Proposal

修 `prompts/actions/requirements-clarification.md` 提示词，使其成为清晰的**受理阶段澄清
指南**，并堵住接手上下文丢失的洞：

1. **澄清问答在受理阶段进行、不得跳过**：提示词明确澄清问答在受理阶段（正式流程启动
   之前）进行——一次只问一个有实质影响的决策、基于仓库事实、不套固定问卷；除非确无
   会实质改变公开行为、验收或架构的决策需要澄清，否则必须先完成澄清问答、取得用户最
   终确认才能记录 PASS；全文不得把澄清问答或写文件与任何后续流程步骤联系起来。
2. **整合需求在受理阶段写入需求文件**：整合后的完整需求与决策在受理阶段（正式流程启
   动之前）写入需求文件，作为本 run 的验收输入与事实来源。
3. **明确"确认"粒度**：呈现完整整合需求与技术方案并取得用户最终确认；PASS 只记录用户
   实际确认的内容。
