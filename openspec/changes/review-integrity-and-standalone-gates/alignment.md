# Requirements Alignment

Date: 2026-08-06
Status: confirmed

## RQ-001 - 审查子代理第一步污染检查

审查子代理收到任务后的第一步 SHALL 核对任务文本完整性：任务只应包含 CLI 组装的块
（`[Shared reviewer contract]` / `[Action]` / `[Gate]` / `[Current requirement]` /
`[Current change]` / `[Action input]` / `[Dispatch]` / `[Result contract]`）。任务块结构
之外、由主代理擅自夹带的具有锚定效应（暴露先前工作/修复、破坏零上下文环境）的附加文本
SHALL 视为污染；发现污染 SHALL 立刻拒绝、不进入审查。

## RQ-002 - 污染定义与拒绝信号

污染 SHALL 定义为：块结构之外、由主代理擅自夹带的、暴露"之前做了什么 / 修了什么"等有锚
定效应、破坏零上下文环境的信息。发现污染 SHALL 返回 `RUNTIME_ERROR`，其消息 SHALL 传达
拒绝原因（检测到何种污染），使主代理可见并处置；`RUNTIME_ERROR` 不计入审查轮次上限。

## RQ-003 - 合法输入例外

`[Action input]` 内的既有用例（qa-design 增量修改所需）与已拍板问题（settled findings）
SHALL 为合法输入、不算污染。

## RQ-004 - 污染检查范围

污染检查 SHALL 覆盖门审、qa-design、qa-review、product-review、start-readiness、
requirements-clarification；SHALL NOT 覆盖开发代理（非零上下文）与 qa-execution（执行
者）。

## RQ-005 - CLI 强制继承操作处理完毕才能重跑

任一项继承判定未处理完毕时（需求产物变更未重新分类、或存在旧快照 PASS 结果待 Carry 决
策、或检测到的中途修改未判定），CLI SHALL 拒绝继续 / 重跑的入口（prepare / claim /
record / snapshot / seal / qa-* / authorize-repair 等），直到处理完。检测到的中途修改
（如已选门 / 动作提示词内容变化、且该目标已有记录结果）属于继承判定；其处置由**主代理
直接完成**——记录该结果"重跑 / 保留旧结论"的决定与理由（不派独立代理），决定记录入口
SHALL 覆盖中途修改场景（不限于修复 / 采纳后），记录完成后该结果的重跑即放行。本条件仅
在存在已记录结果时触发；开发前无记录结果、不触发、不阻塞。

## RQ-006 - 处置命令豁免

`carry`（含中途修改场景的"重跑 / 保留旧结论"决定记录，由主代理直接完成）/
`requirement` / `settle-findings` SHALL 为继承处置命令、豁免 RQ-005 硬闸。

## RQ-007 - CLI 强制恢复中断子代理

续用判定三分支（CLI 强制）：
- **客观因素 + 未变 → 必续用**：中断原因 = 客观因素（API 瞬时原因 429/503/402 等）且需求 /
  方式 / 意图均未变化时，被中断且未出结果的已认领子代理 SHALL 必须恢复原代理（同一身份、
  同一派发），CLI SHALL 拒绝 prepare 同目标新派发并指示恢复原派发 / 原代理。
- **有任何变化 → 不拦**：需求 / 方式 / 意图 / 快照 / 任务任一变化 → SHALL NOT 拦截，允许新
  派发。
- **一切未变 + 无中断原因 → 问用户**：需求 / 方式 / 意图均未变但无已记录中断原因时，CLI
  SHALL 强制询问用户决策（不允许自动续用、也不允许自动放行新派发），由用户决定续用或重开。

## RQ-008 - 续用例外

需求 / 方式 / 意图 / 快照 / 任务任一变化、或中断原因非客观因素时 SHALL 不受 RQ-007 限制、
可开新派发。用户有权主动中断 / 重开（属意图变化、不拦）；主代理 SHALL 无破例权——"一切未
变 + 无中断原因"时的决策 SHALL 由用户作出（RQ-007 第三分支），主代理不得自行定夺。

## RQ-009 - 续用范围与审计

RQ-007 SHALL 覆盖开发 / 修复派发与全部审查派发。续用完成的派发 SHALL 保持同一身份、同
一结果映射，可经生命周期模块 start / stop 配对认证（既有 `VerifyDispatch`）。

## RQ-013 - 中断原因由 CLI 自动记录

CLI SHALL 通过宿主生命周期 hook 在子代理中断时**自动捕获并记录中断原因**（宿主事件携带的
原因字段，含 HTTP 错误码 429/503/402 等），不依赖任何代理自觉。中断原因记录 SHALL 适配
Claude Code 与 Codex，Cursor 在可行时适配。宿主未提供原因时记录为"未知"。按 RQ-007 三分
支判定：原因 = 客观因素且未变 → 强制续用；有变化 → 不拦；未变 + 无原因（含"未知"）→ 强
制询问用户。被中断派发的生命周期校验 SHALL 接受"start 事件 + 已记录中断原因"作为中断凭
证（而非 REJECTED）。

## RQ-010 - 门单跑 / 选几个跑（完全脱离流程）

SHALL 提供新能力：一个或多个门完全脱离 run 运行；审查对象为工作树 vs HEAD 的完整改
动（**默认含未跟踪新文件**），审查者智能判断完整 diff 内容；用户可指定逻辑范围（指定
时按指定范围审查）；无需需求文档；使用轻量零上下文审查者（不做 claim / 生命周期绑
定）；结果仅展示、不持久化，结果展示 SHALL 明确标注"脱离 run 的快速检查、非正式结论、
未持久化"，避免与正式门结论混淆。

## RQ-011 - 单跑复用共享契约

单跑门 SHALL 复用共享审查者契约（`prompts/reviewer-base.md`），因此 RQ-001 污染检查在单
跑中自动生效；RQ-007 续用不适用于单跑（无持久化派发，中断即重跑）。

## RQ-012 - 边界

本变更 SHALL NOT 引入对抗性加固、权限 / 不可变文件故障注入、不受支持平台的兼容路径或框
架层，除非已确认需求明确要求。提示词与文档改动 SHALL 优先修改既有文件、不新增，新增文
本精简克制。
