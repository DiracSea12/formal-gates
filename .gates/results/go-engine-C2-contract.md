# C2 替换单元合同：证据内容摘要原语（G1a 第二项）

基线为 C1（候选 `20b0422`，记录提交 `a756cde`，准入已放行）。

> 边界分析在实施前完成，依据是下面"范围判定"里列出的实测与代码事实；本文档与实施一并落盘。

## 职责边界

**做**：读取一个证据文件的字节，给出其内容证明（`sha256` 与 `size`）；无法读取时给出带原因的拒绝。

**不做**：

- 不判断该文件属于哪个证据族（宿主可执行绑定、作业流日志、原生来源文件、交接包）。
- 不写文件、不做原子替换、不读时钟或随机数、不访问网络。
- 不比较证明集合，也不产出"证据已变化"这类策略措辞——见下方范围判定。

## 输入与输出

| 项 | 内容 |
| --- | --- |
| 输入 | `path`：调用方格式化好的路径字符串 |
| 输出（成功） | `{"sha256": <64 hex>, "size": <int>}` |
| 输出（拒绝） | `EVIDENCE_MISSING: {path}` |

桥接操作：`file-proof`，载荷 `{"path": "..."}`，返回 `{"ok": true, "proof": {...}}` 或 `{"ok": false, "refusal": "EVIDENCE_MISSING: ..."}`。

**路径格式化留在调用方**：拒绝消息里的路径按调用方构造的原样呈现，因此 `str(path)` 由 Python 侧给出，Go 只负责读与报错。这样既保持了逐字不变的措辞，也不引入第二套路径规范化。

## 受影响调用方

`file_proof` 是真正的共用原语，7 个模块、约 15 个调用点：

| 模块 | 用途 |
| --- | --- |
| `infra.py` | `Store.verify_process` / `verify_evidence` 校验作业流与比较输入 |
| `native_hosts.py` | 宿主绑定与原生来源证据校验 |
| `native_dsh.py` / `native_zcode.py` | 原生来源文件证明、宿主可执行绑定 |
| `job.py` | 作业 stdout/stderr 流证明 |
| `handover.py` | 交接包内文件与差异证明 |
| `feedback.py` | 反馈来源证明 |
| `workers.py` | 作业输入文件证明 |

## 范围判定（为什么只搬这一层）

**不搬 `verify_process` / `verify_evidence`**：它们比较的是 `digest(request)`，即 Python 命名空间下的 JSON 规范化摘要。实测确认两侧摘要互不比较、是各自独立的命名空间：

```text
值 {"a":"x<y & z"}
Python canonical 字节  b'{"a":"x<y & z"}'
Python digest          cfe273e8e26377ee952f273b7ce8e8b0520fa24221f325355288d556618b144b
Go 编码（bridge 响应） "x\u003cy \u0026 z"   ← Go 转义 < 与 &
```

Go 的 `harness.Digest` 只用于 `revision` 与 `binding`（Go 内部自比），Python 的 `digest` 只用于操作 ID、反馈与交接键。因此**把规范化搬到 Go 会改变 Python 侧的每一个摘要**，属于方案 12.2 所说的"格式变更需另作版本化迁移"。在这件事决定之前，`verify_process` 无法整体搬动。

**不搬 `verify_source` / `validate_binding`**：这两处是宿主编配器的生命周期策略（`HOST_CHANGED` / `EVIDENCE_CHANGED` 的措辞与适用对象），随宿主适配器在 G2b/G2c 迁移，不混进"只读计算"这一块。

**不搬 `read` / `canonical` / `atomic`**：`read` 是通用 JSON 读取（异常面含 `UnicodeDecodeError`/`JSONDecodeError`/`FileNotFoundError`），是基础设施而非证据完整性业务；`canonical`/`atomic` 见上一条。

**因此 G1a 内所有能在不做格式迁移的前提下搬动的只读计算，在本单元后即已搬完。**

## 不变量

1. 拒绝措辞逐字不变：`EVIDENCE_MISSING: {path}`。
2. 证明形状不变：恰好 `sha256` 与 `size` 两个字段，`size` 为整数。
3. 语义不变：跟随符号链接读到目标内容；目录、断链、不可读、不存在一律拒绝。
4. 桥接失败形状与退出码不变。

## 必需用例

| 用例 | 判据 |
| --- | --- |
| 空文件、单字节、ASCII、CRLF、UTF-8 非 BMP | 证明与内容直接哈希一致 |
| 含 NUL 与高位字节的二进制 | 同上 |
| 大文件（≥1 MiB） | 同上 |
| Unicode 文件名、嵌套路径 | 同上 |
| 指向文件的符号链接 | 证明等于目标内容 |
| 断链、目录、不存在、不可读 | 拒绝，措辞与迁移前一致 |
| 内容变化 | 证明随之变化 |

## 适用宿主

纯只读计算，**不涉及宿主协议、进程、连接、权限或工具继承**，不需要原生定向验收。原生验收授权关口仍在 G2b 之前。

## 已测量的开销

| 场景 | 迁移后（Go） | 迁移前（进程内） |
| --- | --- | --- |
| 小文件 | 6.1 ms/次 | 0.036 ms/次 |
| 4 MB 文件 | 10.7 ms/次 | 3.1 ms/次 |

每次调用约 6 ms 是跨进程的固定成本。调用点都是"每次角色完成数个文件"的量级，可接受；若将来出现需要批量证明的调用方，应加一个批量操作，而不是改回逐调用机制。此项按方案第 15 节记录为实测性能数据。
