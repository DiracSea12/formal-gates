# Requirements Clarification Artifacts

Formal requirements PASS is one closed schema-version-2 JSON artifact generated by the CLI. The semantic owner supplies only confirmed requirement text, decisions, per-item dispositions, coverage judgments, and messages as positioned scalar command arguments. There is no AI-authored semantic JSON input. AI must not handwrite the alignment, decision, requirements envelope, JSON keys/objects/arrays, paths/hashes/bindings, counts, dimension IDs, RQ mappings, or PASS verdict. Markdown may explain the result but has no admission authority. Old Markdown, schema-version-1, and legacy AI JSON-input workflows restart.

`formal-gates artifact compose-requirements` writes the alignment, decision, and requirements artifact together, calculates their evidence references, and validates the final result before retaining it. It never overwrites an existing output and leaves no partial formal output after rejection.

The payload contains exactly:

- `requirementSource`, `alignment`, `totalAlignmentItems`, optional `previousAlignment`
- `openQuestionIds`, `openBlockers`, `droppedQuestionIds`, `droppedQuestionApproval`
- `userConfirmation`, `coverageScan`, `scopePreservation`, `taskProof`
- `dimensionCoverage`, `decision`, `coveredTargets`, `downstreamPermission`

Every evidence reference contains exactly a run-relative `/` path and lowercase SHA-256. Required arrays are present even when empty. Optional fields are omitted, never `null`.

The alignment JSON contains exactly schema version, workflow, snapshot, and non-empty `items`. Each item contains stable `RQ-###` ID, requirement or question, source, why it matters, status, user answer, downstream effect, document impact, and evidence needed. PASS admits only approved `CONFIRMED`, `DEFERRED`, `DROPPED`, or `WITHDRAWN` dispositions. The orchestrator binds one ordered `--alignment-id` from the confirmed catalog; the semantic owner submits a 1-based `--alignment` position followed by exactly eight scalar `--alignment-value` arguments in the documented field order. The CLI projects IDs and values into every generated artifact.

The decision JSON contains exactly schema version, workflow, snapshot, `USER_CONFIRMATION`, boolean confirmation, original user text, alignment reference, approved current IDs, approved removed IDs, and approval scope. Current IDs, removed IDs, payload counts, and continuity must agree exactly.

`dimensionCoverage` contains `DIM-01` through `DIM-13` exactly once. The semantic owner submits each 1-based `--dimension` position with status and message scalars, plus one or more paired `--dimension-ref/--dimension-ref-item` positions. The CLI writes every fixed dimension ID and mechanically resolves final `alignmentIds`. Covered targets are precise repository-relative documents or bundles supplied as repeatable CLI arguments.

Compose, validate, and record through the existing CLI:

```bash
formal-gates artifact compose-requirements --root <repo> --run-dir <run-dir> \
  --workflow-id <id> --change-snapshot <snapshot> \
  --requirement-source <approved-source> \
  --alignment-id <RQ-###> --alignment 1 \
  --alignment-value '<requirement-or-question>' --alignment-value '<source>' \
  --alignment-value '<why-it-matters>' --alignment-value CONFIRMED \
  --alignment-value '<user-answer>' --alignment-value '<downstream-effect>' \
  --alignment-value '<document-impact>' --alignment-value '<evidence-needed>' \
  --user-original '<confirmed-user-text>' --coverage-scan PASS \
  --scope-status PASS --scope-message '<scope-judgment>' \
  --task-status PASS --task-message '<task-proof-judgment>' \
  --dimension 1 --dimension-status COVERED \
  --dimension-message '<coverage-judgment>' \
  --dimension-ref 1 --dimension-ref-item 1 \
  --covered-target <document-or-bundle> [--covered-target <document-or-bundle> ...] \
  --output-dir <restricted/requirements> \
  [--previous-alignment <restricted/previous-alignment.json>]

formal-gates artifact validate --root <repo> --file <requirements.json> \
  --gate requirements-clarification-gate --workflow-id <id> --change-snapshot <snapshot>

formal-gates workflow record-stage --worktree <repo> --run-dir <run-dir> \
  --gate requirements-clarification-gate --verdict PASS --artifact <requirements.json> \
  --workflow-id <id> --change-snapshot <snapshot>
```

Repeat the positioned alignment group once per `--alignment-id`. Repeat the dimension group so positions 1 through 13 each occur exactly once, with at least one alignment reference per dimension. Duplicate, missing, out-of-range, empty, `PENDING`, or illegal values are rejected before any target or composition proof is written.

Recording validates every typed rule first, creates one deterministic evidence closure without a reviewer receipt, and atomically replaces authoritative state. Any rejection leaves prior state byte-identical.
